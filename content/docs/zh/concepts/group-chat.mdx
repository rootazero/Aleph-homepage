---
title: "群聊"
description: "具有基于人格的协作讨论的多代理群聊，跨越任何消息通道。"
---

`group_chat` 模块为多人格协作讨论提供通道无关的编排。多个具有不同人格的代理可以参与共享对话，每个代理贡献其专业知识以协作解决问题。

## 设计理念

1. **人格驱动** — 每个参与者具有不同的角色、专业知识和通信风格
2. **通道无关** — 通过 Discord、Telegram、CLI 或任何连接的接口工作
3. **共享会话** — 所有参与者看到完整的对话上下文

## 核心组件

### GroupChatOrchestrator

管理整体聊天流程：

```rust
pub struct GroupChatOrchestrator {
    session: GroupChatSession,
    personas: Vec<Persona>,
    coordinator: GroupChatCoordinator,
}
```

### GroupChatCoordinator

确定轮到谁以及他们应该做什么：

```rust
pub struct GroupChatCoordinator;

impl GroupChatCoordinator {
    pub fn next_speaker(
        &self,
        session: &GroupChatSession,
    ) -> Option<&Persona> { /* ... */ }

    pub fn build_persona_prompt(
        &self,
        persona: &Persona,
        context: &ChatHistory,
    ) -> String { /* ... */ }
}
```

**系统提示词处理：** 系统提示词通过适当的 `.with_system()` 参数传递，而非嵌入在用户消息文本中。

### GroupChatExecutor

为每个参与者运行 LLM 调用：

```rust
pub struct GroupChatExecutor {
    provider: Arc<dyn LlmProvider>,
}
```

### Persona

定义参与者的身份：

```rust
pub struct Persona {
    pub id: String,
    pub name: String,
    pub system_prompt: String,
    pub expertise: Vec<String>,
}
```

**预设：** `PersonaRegistry` 包括预定义的人格（例如，"coder", "reviewer", "architect"）。

### GroupChatSession

维护对话状态：

```rust
pub struct GroupChatSession {
    pub messages: Vec<ChatMessage>,
    pub participants: Vec<String>,
}
```

## 协议

群聊通信的消息类型：

```rust
pub enum GroupChatMessage {
    Text { from: String, content: String },
    Join { persona: String },
    Leave { persona: String },
    System { content: String },
}
```

## 意图类型

`intent` 模块提供从旧意图检测管道保留的轻量级类型定义：

```rust
pub enum TaskCategory {
    Code,
    Search,
    FileOperation,
    // ... 等
}

pub enum DetectionLayer {
    L2Heuristic,
    L3Llm,
}
```

**注意：** 检测/分类管道已被移除，转而支持 LLM 原生工具选择。仅保留共享类型定义。

## 安全属性

- **UTF-8 安全** — `char_indices()` 用于截断，`.chars().count()` 用于长度
- **确定性排序** — `list_presets()` 返回排序结果
- **无锁中毒** — 使用 `tokio::sync::Mutex`
- **无 SQL 注入** — 此模块中无数据库查询
