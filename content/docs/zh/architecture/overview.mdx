Aleph 采用五层横向架构，构成一条清晰的处理流水线：**接口层**、**网关层**、**编排层**、**执行层**和**存储层**。每条用户消息自上而下贯穿这些层；每个响应自下而上返回。本页将展示完整的系统架构，说明模块之间的依赖关系，并追踪请求在整个生命周期中的流转。

如需深入了解各子系统，请参阅 [Gateway 架构](./gateway)、[Harness](./harness)、[会话管理](./sessions)、[工具架构](./tools) 和 [记忆系统](./memory)。

### 第一层：接口层

最上层包含所有客户端应用。每个客户端——无论是原生 macOS 应用、Tauri 桌面应用、终端 CLI，还是 Telegram/Discord 机器人——都通过同一个 WebSocket 端点 `ws://127.0.0.1:18790/ws` 连接到 Gateway。通信采用 JSON-RPC 2.0 协议，这意味着所有客户端无论平台如何都使用相同的协议。

### 第二层：网关层

Gateway 是控制平面。它接受 WebSocket 连接，解析 JSON-RPC 消息，将其路由到正确的处理程序，并管理会话、事件和认证。它还承载接口注册表（跟踪活跃聊天集成）、配置热重载监视器，以及用于后台任务的定时调度器。详情请参阅 [Gateway 架构](./gateway)。

### 第三层：编排层

编排层为每个传入请求解析 `AgentDef` 和 `FlowSpec`，组装 `HarnessDeps`（注入 `SessionService`、`ToolService`、`Sandbox` 和 `AiProvider`），并分派给 `HarnessRunner::run`。该层将路由关注点与执行逻辑分离，使 Gateway 保持轻量的控制平面。编排层与 Harness 的交互请参阅 [Harness](./harness)。

### 第四层：执行层

Harness 层运行核心智能循环。当消息到达时，`AgentHarness` 执行 **Think→Act** 周期，包括上下文预算管控、停止钩子（stop-hook）评估和可选的压缩：它在预算限制下收集上下文，调用大语言模型（LLM）做决策，按需执行工具，评估停止钩子和安全守卫，并在需要时压缩历史记录。`ToolService` 处理工具执行，而守卫则强制执行迭代上限和令牌预算等安全限制。完整周期请参阅 [Harness](./harness)。

### 第五层：存储层

底层提供持久化存储和状态管理。**Memory** 使用 SQLite 配合 `sqlite-vec` 扩展进行向量搜索，同时支持 Markdown 笔记和 WikiLink 图。**Resilience** 在 SQLite 中存储任务恢复和状态。**Config** 通过 TOML 文件和密钥管理持久化设置。详情请参阅 [记忆系统](./memory)。

## 数据流：请求生命周期

当用户发送消息时，会触发以下序列：

```
Client Request (JSON-RPC over WebSocket)
    │
    ▼
┌─────────────────────────────────────────────────────┐
│ Gateway: InboundRouter                              │
│   • Parse JSON-RPC message                          │
│   • Route to appropriate handler                    │
│   • Authentication check (if enabled)              │
│   • Construct FlowRequest { agent_id, input, ... }  │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────┐
│ Orchestrator                                        │
│   • Resolve AgentDef + FlowSpec                     │
│   • Build HarnessDeps (SessionService, ToolService, │
│     Sandbox, AiProvider)                            │
│   • Dispatch to HarnessRunner::run                  │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────┐
│ AgentHarness: Think → Act loop                      │
│   1. Context: Apply budget, preflight prep          │
│   2. Think: Call Thinker (LLM) for decision         │
│   3. Act: Execute tools via ToolService             │
│   4. Stop-hook: Evaluate completion / guards        │
│   5. Compact: If overflow, compact history          │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────┐
│ FlowOutcome → Gateway renders response              │
│   • Stream events via TraceSink / EventBus          │
│   • Final response as JSON-RPC result               │
│   • Session history persisted to SQLite             │
└─────────────────────────────────────────────────────┘
```

### 工具执行子流程

当 Thinker 决定调用工具时，执行分支会经过 Dispatcher 和 Engine：

```
Thinker Decision (tool_use)
    │
    ▼
┌─────────────────────────────────────────────────────┐
│ Dispatcher                                          │
│   • Analyze tool request                            │
│   • Check permissions (ToolFilter)                  │
│   • Risk evaluation                                 │
│   • Confirmation flow (if needed)                   │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────┐
│ Engine                                              │
│   • Lookup tool (Builtin / MCP / Extension)         │
│   • Deserialize arguments                           │
│   • Execute with timeout                            │
│   • Capture output                                  │
└─────────────────────────────────────────────────────┘
    │
    ├─── Builtin Tool (AlephTool trait)
    │       • Direct Rust execution
    │
    ├─── MCP Tool (Model Context Protocol)
    │       • JSON-RPC to external process
    │
    └─── Extension Tool (WASM / Node.js)
            • Plugin runtime execution
```

Exec 类工具（`code_exec`、`bash_exec`）在工具与进程执行之间还会经过额外的**沙箱层**（`src/sandbox/`）。沙箱负责每会话工作区配置（`~/.aleph/workspaces/{session_id}/`）、能力强制执行，以及通过 `OsSandboxDriver` 实现操作系统级别的 seatbelt 隔离。

## 设计模式

Aleph 在代码库中采用了多种 Rust 惯用设计模式。

### 上下文模式

将相关函数参数分组到专用结构体中，减少参数膨胀并支持构建器模式：

```rust
// Before: 7 parameters passed directly
legacy_agent_loop.run(request, context, tools, identity, callback, abort_signal, initial_history).await

// After: structured deps + FlowRequest
let deps = HarnessDeps { session, tool_service, sandbox, provider, trace_sink };
let flow = FlowRequest::new(agent_id, input, identity)
    .with_abort_signal(abort_rx);
HarnessRunner::run(flow, deps).await
```

**优势：**
- 可扩展性：无需破坏性变更即可添加参数
- 可读性：参数分组清晰
- 类型安全：编译时验证
- 人体工学：可选参数使用构建器模式

### 新类型模式

将原始类型包装在不同的结构体中，以实现编译时安全。你无法意外地将 `SessionId` 传递给需要 `ExperimentId` 的地方：

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct ExperimentId(String);

impl ExperimentId {
    pub fn new(id: impl Into<String>) -> Self { Self(id.into()) }
    pub fn as_str(&self) -> &str { &self.0 }
}

impl Deref for ExperimentId {
    type Target = str;
    fn deref(&self) -> &Self::Target { &self.0 }
}
```

**新类型目录：**
- **IDs**: `ExperimentId`, `VariantId`, `ContextId`, `TaskId`, `SubscriptionId`
- **Collections**: `Ruleset`（权限规则）
- **Values**: `Answer`（问题响应）

### FromStr Trait 模式

为代码库提供统一的解析接口：

```rust
impl FromStr for TaskStatus {
    type Err = String;
    fn from_str(s: &str) -> Result<Self, Self::Err> {
        match s.to_lowercase().as_str() {
            "pending" => Ok(Self::Pending),
            "running" => Ok(Self::Running),
            _ => Err(format!("Invalid TaskStatus: {}", s)),
        }
    }
}

// Usage
let status: TaskStatus = "pending".parse()?;
```

**已实现于：** `FactType`、`HookKind`、`DeviceType`、`TaskStatus`、`RuntimeKind` 以及 10 余种其他类型。

## 协议适配器系统

Aleph 通过分层协议适配器架构支持多个 AI 提供商：

| 层 | 类型 | 示例 |
|-------|------|---------|
| **Built-in** | 编译型 Rust | `OpenAiProtocol`, `AnthropicProtocol`, `GeminiProtocol`, `OllamaProvider` |
| **Configurable** | YAML 热重载 | `~/.aleph/protocols/` 中的自定义协议，扩展内置或完全自定义 |
| **Extension** | 插件 | WASM/Node.js 协议（未来） |

`ProtocolRegistry` 通过先检查动态（YAML）协议，再检查内置协议来解析协议名称。YAML 协议定义在文件变更后 600ms 内通过 `notify-debouncer-full` 热重载。

## 身份与安全

一个不可变的 `IdentityContext` 从会话创建到工具执行贯穿整个执行链。这实现了细粒度的基于角色的访问控制：

- **Owner** 会话拥有所有工具的完全访问权限
- **Guest** 会话携带 `GuestScope`，限制可用工具及会话过期时间
- **Anonymous** 会话默认被拒绝

`PolicyEngine` 在 Executor 级别执行无状态权限检查，确保每个工具调用在执行前都经过授权。

### 安全属性

1. **不可变性**：`IdentityContext` 创建后无法修改
2. **权限冻结**：Guest 作用域在会话创建时冻结
3. **无状态检查**：`PolicyEngine` 无可变状态
4. **授权证书**：身份一次性构建并向下传递
5. **故障安全**：缺失或无效的元数据默认回退到 Owner（向后兼容）
