## 存储架构

### 四 Trait 后端设计

存储层使用**四个独立的 trait**，而非单一存储。每个调用者只依赖其所需的能力：

```rust
// src/memory/store/mod.rs
pub trait NoteStore: Send + Sync { /* ... */ }
pub trait RawMemoryStore: Send + Sync { /* ... */ }
pub trait DreamStore: Send + Sync { /* ... */ }
pub trait CompressionStore: Send + Sync { /* ... */ }
```

四个 trait 均由 `SqliteMemoryBackend` 实现：

```rust
pub struct SqliteMemoryBackend {
    db: Arc<Mutex<Connection>>,
}

pub type MemoryBackend = Arc<SqliteMemoryBackend>;
```

### 数据库结构 (SQLite + sqlite-vec)

#### 核心表

| 表 | 用途 |
|---|---|
| `raw_memories` | 会话记录、附件文本、`is_processed` 标记 |
| `notes_index` | 知识笔记元数据（标题、分类、标签、哈希） |
| `notes_links` | 双向维基链接图 |
| `notes_fts` | 笔记内容的 FTS5 全文索引 |
| `notes_vec_map` | 将 `(path, agent_id)` 映射到数字 rowid |
| `notes_vec_{dim}` | sqlite-vec 虚拟表 (768/1024/1536 维度) |
| `memory_events` | 不可变事件日志（事件溯源变更） |
| `context_anchors` | 事实到会话来历的关联 |
| `dream_status` | 日常/周度梦境运行追踪 |
| `daily_insights` | 梦境守护进程输出缓存 |

#### sqlite-vec 虚拟表

```sql
-- 按嵌入维度创建
CREATE VIRTUAL TABLE notes_vec_768 USING vec0(
    embedding float[768]
);
CREATE VIRTUAL TABLE notes_vec_1024 USING vec0(
    embedding float[1024]
);
CREATE VIRTUAL TABLE notes_vec_1536 USING vec0(
    embedding float[1536]
);
```

`notes_vec_map` 表将人类可读的 `(path, agent_id)` 对桥接到 vec0 表所需的数字 rowid。

## 检索流水线

### NoteFactRetrieval

知识笔记的主要检索接口：

```rust
// src/memory/note_retrieval/mod.rs
#[async_trait]
pub trait NoteFactRetrieval: Send + Sync {
    async fn retrieve(
        &self,
        query: &str,
        agent_id: &str,
        limit: usize,
    ) -> Result<Vec<ScoredFact<MemoryFact>>, AlephError>;
}
```

### 混合搜索 (向量 + FTS)

```
查询
  ├── 向量搜索 (sqlite-vec) → 带距离分数的候选
  ├── FTS 搜索 (FTS5) → 带匹配分数的候选
  └── RRF 融合 → 统一排序列表
```

倒数排序融合 (RRF) 公式：
```
RRF_score = Σ 1 / (k + rank_i)
```
其中 `k = 60`（常数），`rank_i` = 来源 `i` 的排名。

### 评分流水线 (6 个阶段)

| 阶段 | 描述 | 默认 |
|---|---|---|
| `cosine_rerank` | 混合向量搜索得分与实时余弦相似度 | 启用 |
| `recency_boost` | 为最近创建的事实添加增量 boost | +0.1 |
| `length_normalization` | 惩罚过长的内容 | 启用 |
| `time_decay` | 按年龄的指数衰减，下限 0.5 | 半衰期 30 天 |
| `hard_min_score` | 丢弃低于阈值的候选 | 0.35 |
| `mmr_diversity` | 最大边际相关性 — 将接近重复项推迟到尾部 | λ = 0.5 |

**已删除阶段：** `importance_weight`（在主权清理中移除）。

## 后台处理

### 压缩服务

在空闲时刻实时运行：

```
原始记忆 (is_processed = false)
  → SessionCompactor: 每会话压缩
  → NoteIndexer: 创建/更新知识笔记
  → 标记 is_processed = true
```

### 梦境守护进程

在系统空闲时运行，有两种节奏：

**日常流水线 (5 个阶段)：**
```
[Consolidate] → [Drift] → [Lint] → [Decay] → [DailyDigest]
```

**周度流水线 (6 个阶段)：**
```
[Consolidate] → [Drift] → [Synthesis] → [Lint] → [Decay] → [DailyDigest]
```

```rust
// src/memory/dreaming/mod.rs
pub fn ensure_dream_daemon();
pub fn record_activity();  // 用户活动时调用以重置空闲计时器
```

## 工作记忆组装

### HybridAssembler (Spec 2)

替代了传统的 `ContextComptroller::arbitrate` 路径。生成包含明确插槽的 `MemoryEnvelope`：

```rust
// src/memory/assembler/mod.rs
pub struct MemoryEnvelope {
    pub system_slots: Vec<MemorySlot>,      // 始终注入的事实
    pub user_slots: Vec<MemorySlot>,        // 与用户查询相关的事实
    pub scratchpad: Option<String>,         // 工作笔记
}

pub struct MemorySlot {
    pub content: String,
    pub source: String,
    pub score: f32,
}
```

```rust
#[async_trait]
pub trait WorkingMemoryAssembler: Send + Sync {
    async fn assemble(
        &self,
        query: &str,
        agent_id: &str,
        session_id: Option<&str>,
        budget: AssemblyBudget,
    ) -> Result<MemoryEnvelope, AlephError>;
}
```

### 组装预算

```rust
pub struct AssemblyBudget {
    pub max_tokens: usize,      // 组装记忆的目标 token 预算
    pub min_score: f32,         // 最低事实分数阈值
    pub max_facts: usize,       // 包含的最大事实数
}
```

## 精选热记忆 (Spec A)

手动策划的、关键事实的冻结快照，绕过正常检索：

```rust
// src/memory/curated/mod.rs
pub struct CuratedHotMemory {
    pub facts: Vec<CuratedFact>,
    pub frozen_at: i64,
}

pub struct CuratedFact {
    pub content: String,
    pub priority: u8,        // 1-10，越高越重要
    pub source: String,
}
```

- 通过 `remember` 内置工具创建
- 存储在 `~/.aleph/memory/curated/{agent_id}.json`
- 无条件注入每个提示词（在 token 预算内）
- **冻结快照** — 变更需要显式重新策划

## 记忆扩展 (Spec 4)

用于自定义记忆行为的可插拔扩展：

```rust
// src/memory/extensions/mod.rs
#[async_trait]
pub trait MemoryExtension: Send + Sync {
    fn name(&self) -> &str;
    
    async fn on_memory_created(
        &self,
        event: &MemoryEvent,
        backend: &MemoryBackend,
    ) -> Result<(), AlephError>;
    
    async fn on_memory_retrieved(
        &self,
        query: &str,
        facts: &[MemoryFact],
        backend: &MemoryBackend,
    ) -> Result<Vec<MemoryFact>, AlephError>;
    
    async fn on_session_end(
        &self,
        session_id: &str,
        backend: &MemoryBackend,
    ) -> Result<(), AlephError>;
}

pub struct ExtensionRegistry {
    extensions: Vec<Box<dyn MemoryExtension>>,
}
```

**生命周期钩子：**
- `on_memory_created` — 笔记创建/更新后触发
- `on_memory_retrieved` — 可修改/过滤检索到的事实
- `on_session_end` — 清理或总结

## Memory Reflector (Spec 2)

构建于 `HybridAssembler` 之上的综合层：

```rust
// src/memory/reflector/mod.rs
pub struct MemoryReflector {
    assembler: Arc<dyn WorkingMemoryAssembler>,
    llm: Arc<dyn LlmBackend>,
}

impl MemoryReflector {
    pub async fn reflect(
        &self,
        query: &str,
        agent_id: &str,
    ) -> Result<ReflectionResult, AlephError>;
}

pub struct ReflectionResult {
    pub answer: String,
    pub sources: Vec<MemorySource>,
    pub confidence: f32,
}
```

通过 `memory_reflect` 内置工具暴露。返回连贯的、带引用来源的 LLM 综合答案。

## 事件溯源

每条笔记变更都被捕获为不可变的 `MemoryEvent`：

```rust
// src/memory/events/mod.rs
pub struct MemoryEvent {
    pub id: i64,
    pub event_type: MemoryEventType,
    pub note_path: String,
    pub timestamp: i64,
    pub payload: String,  // JSON
}

pub enum MemoryEventType {
    NoteCreated,
    NoteUpdated,
    NoteDeleted,
    LinkAdded,
    LinkRemoved,
    TagChanged,
}
```

事件支持：
- 所有记忆变更的审计追踪
- 时间旅行查询
- 冲突解决
- 扩展钩子触发

## 安全属性

| 关注点 | 缓解措施 |
|---|---|
| UTF-8 截断 | `chars().take(n)`（从不在字符中间截断） |
| 锁中毒 | `unwrap_or_else(\|e\| e.into_inner())` |
| SQL 注入 | 通过 rusqlite 参数化查询 |
| 向量边界 | 余弦值限制在 `[-1.0, 1.0]` |
| Token 溢出 | AssemblyBudget 强制执行限制 |

## 已删除组件 (主权清理)

以下组件于 2026-04-12 移除：

| 组件 | 替代方案 |
|---|---|
| `MemoryTier` 枚举 | 结构区分（原始记忆 vs 笔记） |
| `MemoryFact.strength` | 移除（由 LLM 决定相关性） |
| `MemoryFact.confidence` | 移除（由 LLM 决定相关性） |
| `ValueEstimator` | 完全删除 |
| `importance_weight` 评分 | 删除 |

理由：**LLM 主权** (R8) — 确定性的"重要性"启发式无法超越 LLM 自身对上下文中什么重要的判断。
